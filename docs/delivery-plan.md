  own process. Bounds apply to shared product inputs/resources, not to private
  application CPU, memory, databases, files, sockets, dependencies, or child
  processes.

## Product and architecture decisions

- Games & Apps remains bundled.
- Spotify and Game Launcher are ordinary Community applications. Core product
  assemblies must not contain their service-specific DTOs, OAuth, API clients,
  process hosts, package identities, assembly/type checks, element/style
  recognition, or known-tree-shape behavior.
- Sandboxed packages retain AppContainer and capability boundaries.
- Explicitly consented full-trust packages run as ordinary current-user
  applications through the generic full-trust runtime.
- Launcher Experience packs remain data-only and host-owned.
- Avalonia replaces only the presentation boundary. Retain Widget SDK/protocol,
  catalog/package/runtime, WidgetBridge backend and authenticated transport,
  lifecycle/trust/persistence/providers, widget domain implementations, and
  Community process boundaries.
- AVP-004 renders the current semantic contract through one generic Avalonia
  adapter. It must not create domain-specific Avalonia pages.
- The production native Microsoft GameInput/Guide owner is authoritative.
  AVP-004 must not add a second C# GameInput owner, another presentation HWND,
  another focus tree, or another bridge transport.
