## Implementation direction

- Bind a native dialog session to the admitted process, HWND and accessibility identity. Use native window events to request reconciliation; retain bounded accessibility fallback for Chromium's reused HWNDs and missing events. Do not scan webpage accessibility content.
- Keep existence, foreground/input eligibility and cancellation progress separate. Pause input on foreign foreground; do not infer closure from that or a failed query.
- Request close against the identified dialog, retain the lease/placement until confirmed absence, and reconcile a surviving chooser on overlay re-entry. Unknown remains unknown with a usable cancel/retry path.
- Record transitions, cancellation causes, foreground/target handles, input rejection reasons and pointer resets with bounds/rate limits; no page text, titles, credentials or media.
- Validate repeated open/change-share, cancellation, temporary foreground changes, hide/reopen, reused HWNDs, mouse/controller handoff, and published-build diagnostics. No Discord DOM instrumentation or account probes.

## Findings and implementation

- Added an additive native session-observation export. Admission identifies the unique chooser in the authorized browser process; subsequent checks/close requests bind to its HWND and hashed UI Automation runtime identity. Old native query exports preserve their original behavior. No window titles or webpage accessibility trees are read.
- Process-scoped WinEvent window hints and foreground events trigger rechecks, with a bounded 500 ms fallback after admission (150 ms during acquisition/absence confirmation). These are Win32 event hints, not a claim that Chromium reliably emits UI Automation WindowClosed events.
- Native closure requests can return S_OK while the chooser remains present. Tests observed this directly. The controller now requests Escape only for the admitted foreground chooser, verifies actual absence, and retains its modal/placement lease until then. It recovers focus from the overlay's own foreground for an explicit cancellation, never from an unrelated app.
- Hiding the host can make Chromium's chooser accessibility subtree disappear without completing the sharing request. Host visibility now invalidates old query results and pauses observation while hidden; re-entry can uniquely rebind recreated accessibility objects for the same admitted request. Normal overlay hiding first closes the chooser while its host remains visible. A user re-open cancels the pending hide but still lets the native cancellation finish.
- Expanded-browser placement previously also collapsed independently when visibility became false. It now retains chooser-owned placement until session completion. Input eligibility and existence remain separate; temporary foreign foreground pauses input instead of cancelling the dialog.
- Explicit `AllowSetForegroundWindow` grants the owned browser foreground eligibility before releasing the request when WidgetRail owns foreground. Grant success/failure is logged; it is not claimed as proof of physical controller delivery.
- Diagnostics now include admission/identity, foreground, circle visibility transitions, rejected-input reason changes, cancellation reasons/results, and a two-second routing summary while the dialog is visible. The controller writer reports failures to the durable frontend log, with one startup health observation. No raw webpage content or key text is logged.
- Prototype checks exposed two defects in the new implementation (hidden absence being treated as closure and cancellation retries waiting on their own inspection); both were corrected before candidate delivery. The three-round sequence now passes chooser checks. A follow-on unpin assertion assumed widget interaction despite intentional tray focus after reopen; evidence recorded `samePage=True, interactive=False, focus=Overlay.Widget.webapp-a`. The fixture now enters that selected tray item with A before continuing, preserving production focus behavior.
- Builds pass; managed shell lifetime tests 234/234 and input/client tests 67/67 pass. Native synthetic controller/ABI policy tests pass without hardware initialization.
- Combined `session-07.json` passes 168 checks through shutdown: three chooser rounds (share, delayed hide/reopen cancel, B cancel), temporary foreign foreground, mouse/controller handoff, exact synthetic video delivery, prior-stream preservation, notifications, memory policy, layer order, pins/pop-outs and recovery. The native circle raster is visible and was reviewed.
- The separate user-expanded repeat fixture needed to re-expand before every round: its original setup expanded only once, although the end of each round deliberately collapsed. That fixture correction does not change production behavior. `expanded-02.json` now passes 65 checks through shutdown, including share → cancel/audio-toggle → share while preserving prior streams and user-owned expansion.
- Review covered native ABI widths/calling convention, callback rooting and unhooking, runtime-identity admission, stale-result generations, bounded observation and retry, no focus acquisition from unrelated apps, cancellation/foreground separation, deferred-hide supersession, and preservation of the original pin-focus restoration order. These tests prove the native UI/pointer transport and lifecycle paths, not physical controller delivery. The foreground grant/re-entry changes and durable diagnostics are ready for physical verification; do not claim a confirmed cause for that symptom.
